# 代码评审报告模板（11 节）

> 第 0 节必须写明**基准等级**。L0 报告不得出现"符合设计"（gate 强制）。

```markdown
# <项目> 代码评审报告
基准：L2（设计已过审）        # L0 仅代码 / L1 设计对照 / L2 全量对照

- 评审模式：全量（整仓代码 vs 全部设计文档）／增量 <from>..<to>（代码变更 + 涉及的设计章节）
- 评审基线：全量 → 工作区 HEAD <sha>（整仓）；增量 → <from>..<to>，改动 N 文件 +A/-D 行
- 代码范围：<整仓（排除 vendor/build/third_party）／变更文件清单>
- 设计基准：`specs/design/`（全部文档 ／ 涉及章节清单）；state=<closed|confirm|draft>
- 约束：只读，不改代码

## 0 流程执行摘要

| 步骤 | 状态 | 耗时 | 覆盖 |
|---|---|---|---|
| B0 契约校验 + 体检 | done | 2m | 子模块 3 个均检出 |
| B1 锁范围 | done | 1m | 12 文件 +340/-88 |
| B3 抽断言 | done | 2m | 369 条 |
| B4 机械核对 | done | 3m | found 330 / missing 39 |
| B5 逐镜头扫描 | done | 26m | 20/20 |

| B7a/b/c 红-蓝-裁 | done | 14m | 18 指控 |
| B8 定级成文 | done | 4m | 15 条 |

- gate 校验：通过（<时间>）
- 中断次数：<N>

## 7 正确性与安全发现（20 镜头）

> **报告自包含**：读者不打开 `05-findings.json` 也能判断「哪个代码文件、哪个模块、哪个镜头、哪条流程、错在哪、怎么改」。
> 该 JSON 只是机器可读证据（gate / 账本 / task.md 用），不是给人看的载体。

### 7.1 按模块索引

| 模块 | 代码文件 | 设计对照 | P0 | P1 | P2 | P3 |
|---|---|---|---|---|---|---|
| <模块名> | <src/...> | <设计文档:行> | <n> | <n> | <n> | <n> |

### 7.2 P0/P1 逐条（四段式，缺一不可）

#### F-001 <一句话现象>（P1，upheld）

- **在哪**：`src/plugin/runtime.cpp:430`（PluginHost::LoadAndStart）＋ 设计对照 `04-插件运行时.md:88`（§3.2）
  - 模块：插件运行时｜镜头：04 错误处理｜功能/流程：插件加载失败处理
- **什么问题**：代码现在是什么行为、违反了什么、缺什么（白话 2–4 句，不复述触发条件）
- **会怎样**：给定触发条件 → 错误行为 → 现场后果
- **怎么改**：1) 改哪个文件哪个函数、加/删/改什么 2) … 3) …（每步可执行）
- **证据**：`if (h == nullptr) { LOG(WARN) << "skip"; }`（`runtime.cpp:430`）

硬性要求：

- 位置必须「代码 `file:line`」+「设计对照 `文档:行`」；禁止 `runtime.cpp:430` 之外的缩写（`430`、`§3.2` 单独出现不算位置）。
- P0/P1 **不许**只给压缩表格，每条都要上述四段。
- 一条发现跨多个文件时全部列出；主改位置在前。

### 7.3 P2/P3（简表，三列齐全）

| 编号 | 位置（代码 file:line / 设计 doc:line） | 问题 | 怎么改 |
|---|---|---|---|
| F-0xx | `src/plugin/x.cpp:88`（§3.2） | 一句话说清偏差 | 一句话说清改哪个函数、加什么 |

P2/P3 可以合并同类，但不许只写「全量见 05-findings.json」。
```

## 基准等级（第 0 节强制）

| 等级 | 判定条件 | 报告标注 | 门禁效力 |
|---|---|---|---|
| L2 | 设计齐全（00/01/02 + 模块 + task.md）+ `state=closed` | `基准: L2（设计已冻结）` | 可作门禁放行依据 |
| L1 | 设计齐全但未冻结（state≠closed） | `基准: L1（设计未冻结）` | 可作门禁，须注明基准未冻结 |
| L0 | 无设计 / draft·explore / 仅部分文档 / 只改代码 | `基准: L0（未做设计对照）` | **不作门禁放行依据** |

L0 是完整评审，不是打折评审：19 个镜头一条不少，只是少了"是否按这份设计做的"这一项判断；镜头 0 在 L0 下跳过并标注（不许用代码反推需求）。

## 批准与 task.md

报告产出后状态停在 `reported`。批准后 `state.mjs approve <reviewDir> --reviewer "<姓名>"` 生成 `task.md`（P0/P1 修复任务、依赖排序、四段式 AI 提示词）并 `closed`。

## Gate I 通过条件

- 无 P0；
- P1 已登记且有关闭计划；
- 欠账白名单内的 DR-6/DR-1 不计入（引用设计评审结论）。
