# 代码评审报告模板（11 节）

> 第 0 节必须写明**基准等级**。L0 报告不得出现"符合设计"（gate 强制）。

```markdown
# <项目> 代码评审报告
基准：L2（设计已过审）        # L0 仅代码 / L1 设计对照 / L2 全量对照

- 评审基线：<base sha>..<head sha>；改动 N 文件 +A/-D 行
- 设计基准：<design commit>（来自交接块 / 或「未过 Gate D，基准可信度低」）
- 约束：只读，不改代码

## 0 流程执行摘要

| 步骤 | 状态 | 耗时 | 覆盖 |
|---|---|---|---|
| B0 契约校验 + 体检 | done | 2m | 子模块 3 个均检出 |
| B1 锁范围 | done | 1m | 12 文件 +340/-88 |
| B3 抽断言 | done | 2m | 369 条 |
| B4 机械核对 | done | 3m | found 330 / missing 39 |
| B5 逐镜头扫描 | done | 26m | 20/20 |
| B6 承诺核验 | done | 8m | 7 任务 |
| B7a/b/c 红-蓝-裁 | done | 14m | 18 指控 |
| B8 定级成文 | done | 4m | 15 条 |

- gate 校验：通过（<时间>）
- 中断次数：<N>

## 1 范围与体检

- 子模块状态表（未检出必须显式声明影响）
- 切片方案

## 2 断言核对结果

| 类型 | 断言数 | found | missing | unverifiable |
|---|---|---|---|---|

- missing 三态归类统计（真缺失 / 改名未回写 / 表达差异）

## 3 漂移清单（DR-1~DR-8，P0→P3）

每条：编号 / DR 类型 / 文档位置 / 代码位置 / 断言原文 / 归因 / 修法

## 4 决策追溯

| D-nnn | 设计要求 | 代码现状 | 一致 | 残留 |
|---|---|---|---|---|

## 5 双向缺口

- 文档有代码无（欠账）
- 代码有文档无（未设计实现）

## 6 task.md 承诺核对

| 任务 | 功能 | 要求 | 约束（负向） | 验收标准 | 勾选可信 |
|---|---|---|---|---|---|

## 7 正确性与安全发现（20 镜头）

每条：【级别】【镜头】位置 / 现象 / 触发条件 / 证据 / 违反不变量 / 影响 / 修法 / 置信度 / 裁断态

## 8 对抗台账

- 指标：成立率 / 有效辩护率 / 升级率 / 未决率（由 08-verdict.json.stats 计算）
- | 指控 | 级别 | 蓝队辩护要点 | 裁定 | 级别变化 |
- 未决项单列，标注「待人工裁定」与裁定人

## 9 结论与 Gate I

- 通过 / 有条件通过 / 不通过
- 合并前必办清单（按依赖排序）

## 10 附录

- 覆盖矩阵（20 × 文件）
- 未核对项（明确列出没看什么）
```

## 基准等级（第 0 节强制）

| 等级 | 判定条件 | 报告标注 | 门禁效力 |
|---|---|---|---|
| L2 | 设计齐全 + state=closed + 有 Gate D 交接块 | `基准: L2（设计已过审）` | 可作门禁放行依据 |
| L1 | 设计齐全 + state=closed，无 Gate D 报告 | `基准: L1（设计未过审）` | 可作门禁，须注明基准未审 |
| L0 | 无设计 / draft·explore / 仅部分文档 / 只改代码 | `基准: L0（未做设计对照）` | **不作门禁放行依据** |

L0 是完整评审，不是打折评审：19 个镜头一条不少，只是少了"是否按这份设计做的"这一项判断；镜头 0 在 L0 下跳过并标注（不许用代码反推需求）。

## 批准与 task.md

报告产出后状态停在 `reported`。批准后 `state.mjs approve <reviewDir> --reviewer "<姓名>"` 生成 `task.md`（P0/P1 修复任务、依赖排序、四段式 AI 提示词）并 `closed`。

## Gate I 通过条件

- 无 P0；
- P1 已登记且有关闭计划；
- 欠账白名单内的 DR-6/DR-1 不计入（引用设计评审结论）。
