# 发现构造、分级与取证（实现侧）

## 1 断言铁律

每条发现必须给出：**文档位置 + 代码位置（file:line）+ 该条断言原文（或触发条件）**。
缺任一项 → 降级为「风险提示」，不进缺陷清单。

## 2 分级

| 级别 | 判据 |
|---|---|
| **P0** | 数据错误/丢失、崩溃、安全问题（可控设备/注入/越权）、**DR-8 假勾选**、违反负向约束 |
| **P1** | 特定现实场景下功能错误；DR-1 无实现；DR-3 行为不符；DR-5 内部矛盾；DR-6 未设计实现 |
| **P2** | DR-2 改名未回写；DR-4 残留；可维护性；镜头 16/17/18 的一般问题 |
| **P3** | DR-7 格式；命名风格 |

**上限**：镜头 19 的模式类发现封顶 P2；镜头 20 违反 CONC-1..5 最低 P1、致故障可 P0，CONC-6/7 为 P2。

## 3 取证格式

```
F-001
- 级别 / 镜头：P1 / 04 错误处理
- 位置：文档 04-插件运行时.md:88（§3.2）；代码 src/plugin/runtime.cpp:430
- 现象：加载失败后继续启动，后续空指针
- 触发条件：插件 .so 存在但符号缺失
- 证据：if (h == nullptr) { LOG(WARN) << "skip"; }  // :430
- 违反不变量：加载失败必须 fail-closed
- 影响：整个插件运行时进入半初始化状态
- 修法：返回错误并逆序卸载已启动插件
- 置信度：high
- 裁断：upheld（A-011）
```

批产物字段（gate 校验）：

```json
{
  "id": "F-001",
  "level": "P1",
  "title": "加载失败后继续启动",
  "location": "src/plugin/runtime.cpp:430",
  "doc_ref": "04-插件运行时.md:88",
  "mechanism": "错误被吞掉",
  "trigger": "符号缺失",
  "evidence": "if (h == nullptr) { LOG(WARN) << \"skip\"; }",
  "invariant": "加载失败必须 fail-closed",
  "impact": "半初始化",
  "suggestion": "返回错误",
  "confidence": "high"
}
```

## 4 去重与排序

- 同位置同机制合并取高级别；不同位置同机制合并为模式化问题（≥3 处标系统性问题，级别上调一档，封顶 P1）。
- 排序按修复依赖，不按文件顺序；每条带 `depends_on`。没有依赖字段的发现不许进必办清单。

## 5 置信度

| 置信度 | 含义 | 用法 |
|---|---|---|
| high | 有代码证据 + 可复现触发条件 | 可作 P0/P1 |
| medium | 代码证据充分但未实测 | 可作 P1，不作 P0 |
| low | 仅静态推断 | 只进风险提示 |

并发类发现拿不出 TSan/Helgrind 等证据时，置信度必须 ≤medium，**不得单独作为 P0 依据**。
